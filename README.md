# Vehicle playback

A static web page that replays 24 hours of public transport vehicle positions
(Sydney, and any other city added to the recorder, e.g. Prague) on a zoomable map: buses,
trains, metro, ferries and trams, moving smoothly between their recorded GPS
reports. A city picker in the panel switches between cities.

**Live site:** https://maxim75.github.io/tfnsw-playback-map/

- Time slider across the day (the strip under it shows when data was recorded),
  play/pause (space bar), 1×–120× speed, jump to a time. Open with
  `#<city>/HH:MM` in the URL to open a city at that time, e.g.
  `…/#sydney/17:30` (`#sydney` alone picks the city; an old-style `#17:30`
  means the first city).
- Filter by mode and route, colour by mode (default), route or speed, fading trails.
  Zoom in for direction arrows and route numbers.
- Built with [MapLibre GL JS](https://maplibre.org) on
  [OpenFreeMap](https://openfreemap.org) vector tiles and
  [deck.gl](https://deck.gl) WebGL layers. No build step, no server code.

## Data

Vehicle positions come from GTFS-Realtime feeds (for Sydney the Transport for
NSW Open Data feeds), recorded every 30 s by
[tfnsw_realtime_recorder](https://github.com/maxim75/tfnsw_realtime_recorder)
(private). Each city's attribution is shown in the panel; Sydney contains
Transport for NSW data, licensed under
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

```
data/cities.json                  cities, with centre, zoom, timezone, attribution, exported date
data/<city>/index.json            day bounds (city time), windows with data, feeds (format 2)
data/<city>/w/<start>.json.gz     one compact file per 10-minute window
```

The page loads only the windows it is about to play. Each window lists its
vehicles once (`[feed_index, vehicle_id, route_id, label, mode]`), with their
reports as delta-encoded columns (format described in the recorder's
`recorder/static_export.py`); a full day is roughly 15 MB per city.

## Creating the vehicle data files

The files in `data/` are generated by `export_static.py` in the recorder
repository from the recordings in its S3 bucket. The site shows one day at a
time per city; exporting a day replaces that city's folder in `data/<city>/`
(other cities are untouched) and updates `data/cities.json`.

### Updating the map (quick reference)

After the one-time setup below, a refresh is: export, check, push. To show
yesterday's full day for every city, run from `tfnsw_realtime_recorder/`:

```bash
for city in sydney prague; do uv run export_static.py --city "$city" --date yesterday --out ../tfnsw-playback-map/data; done
```

then from `tfnsw-playback-map/`:

```bash
git add -A data && git commit -m "Data: $(date -v-1d +%F)" && git push
```

(`date -v-1d` is macOS; on Linux use `date -d yesterday +%F`.)

- **Only one city:** run the export for that city alone; the other cities keep
  their current day.
- **Today so far:** use `--date today`. Re-run it later the same way to add
  the newer windows (each finished window is added 15 minutes after it ends).
- **Another day:** `--date 2026-10-16`. The site holds one day per city, so
  this replaces that city's current day.
- **Remove a city:** delete `data/<city>/` and its entry in `data/cities.json`,
  then commit and push, e.g. for Prague:

  ```bash
  rm -r data/prague
  python3 -c "import json,pathlib; p=pathlib.Path('data/cities.json'); d=json.loads(p.read_text()); d['cities']=[c for c in d['cities'] if c['id']!='prague']; p.write_text(json.dumps(d, indent=1))"
  ```

- **After pushing:** GitHub Pages rebuilds in a minute or two, and browsers
  may keep the previous files for up to 10 minutes (Pages sends
  `Cache-Control: max-age=600`). Hard-refresh (Cmd+Shift+R) or use a
  private window to see the new day immediately.

### 1. One-time setup

Clone both repositories side by side (the recorder repository is private, so
this needs access to it) and install [uv](https://docs.astral.sh/uv/):

```bash
git clone https://github.com/maxim75/tfnsw_realtime_recorder.git
git clone https://github.com/maxim75/tfnsw-playback-map.git
```

In `tfnsw_realtime_recorder/`, create a `.env` with the bucket settings (the
same ones the recorder uploads with):

```
S3_ENDPOINT_URL=https://nbg1.your-objectstorage.com
S3_BUCKET=tfnsw-vehiclepos
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
```

### 2. Export a day

From `tfnsw_realtime_recorder/`:

```bash
uv run export_static.py --city sydney --date 2026-10-17 --out ../tfnsw-playback-map/data
uv run export_static.py --city prague  --date 2026-10-17 --out ../tfnsw-playback-map/data
```

- `--city` is a city id from the recorder's `cities.toml` (default `sydney`).
  Run the command once per city to publish.
- `--date` is a city-local date (`YYYY-MM-DD`), or `today` / `yesterday`
  (the default). A full day takes a minute or two and is roughly 15 MB.
- Only finished windows are exported: each 10-minute window is included 15
  minutes after it ends. Exporting `today` gives the day so far; run it again
  later to add the newer windows.
- Periods without recordings are skipped and show as gaps on the slider.
- By default recordings are read from S3; `--data-dir <dir>` reads local
  recordings (a recorder data directory with the city folders) instead.

The command prints one line per window and a summary, e.g.
`Exported sydney 2026-10-16: 25 windows, 857866 reports, 5.0 MB to ../tfnsw-playback-map/data/sydney in 43 s`.

### 3. Check it locally (optional)

From `tfnsw-playback-map/`:

```bash
python3 -m http.server 8000
```

Open http://127.0.0.1:8000 and play a few times of the day.

### 4. Publish

From `tfnsw-playback-map/`:

```bash
git add -A data && git commit -m "Data: 2026-10-17" && git push
```

`git add -A` also records the deleted files of the previous day's windows. GitHub Pages
rebuilds within a minute or two; to check:

```bash
gh api repos/maxim75/tfnsw-playback-map/pages/builds/latest --jq .status
```

It prints `built` when the new data is live (hard-refresh the page if the old
day still shows).

## Run locally

Any static file server works (opening `index.html` as a file doesn't, as
browsers block its data requests), for example:

```bash
python3 -m http.server 8000
```

and open http://127.0.0.1:8000.
